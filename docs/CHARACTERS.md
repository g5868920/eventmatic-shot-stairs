# Character sprites and future skins

Character art is completely separate from gameplay. The engine moves a 26×26 collision box
(`HERO_WIDTH`) and only asks the renderer to draw "frame N of this player's sheet at the feet
position". Swapping the sheet never changes physics.

## Sheet layout

* PNG, 256×64, transparent background.
* Eight 32×32 frames in a row (frame i at x = i × 32).
* Row y = 0: normal frames. Row y = 32: the same frames in the "hurt" flash colours (white/pink).
* The engine draws the frame so that its bottom row sits on the collision box's feet and its
  centre column is the box's centre: the 26-px box occupies columns 3..28 of the frame. Art may
  use the full 32×32 (a wide cap brim, swinging arms) without affecting collisions.
* Frame use (facing right; the engine mirrors for left):

| i | frame |
|---|---|
| 0 | standing, idle |
| 1 / 2 / 3 | walk cycle (engine plays 2, 1, 2, 3; frame 2 is normally a copy of 0) |
| 4 / 5 | falling, no steering |
| 6 / 7 | falling while steering |

## Defaults

`assets/kid-p1.png` (1P: blue cap, green shirt, starts on the right) and `assets/kid-p2.png`
(2P: red cap, pink shirt, starts on the left) are
generated by `tools/build_sprites.py` from text bitmaps and palettes (`KID`, `KID_PALETTES`).
Edit the bitmap or palette and re-run the script to change the defaults. For a portrait-style
skin, draw the face inside the ~14×10 head area of the standing frame and reuse the body rows.

## Using a custom sheet (e.g. a friend's pixel portrait)

```js
// config.js
players: {
  p1: { label: 'RAE',   keys: {...}, sheet: 'skins/rae.png' },
  p2: { label: 'LINDA', keys: {...}, sheet: 'skins/linda.png' }
}
```

or at runtime before the next round: `ShotStairs.configure({ players: { p1: { sheet: 'skins/rae.png' } } })`
(takes effect on the next page load because sheets are loaded once at start-up).
Any other sprite can be replaced the same way through `SHOT_CONFIG.sprites` using the keys in
`ShotSprites.MANIFEST` (e.g. `{ mug: 'skins/cocktail.png' }`).

No avatar editor or photo upload exists yet; this is only the file-level hook.

## Custom portrait skins (prototype, 2026-11-12)

A visual-only alternative to the classic kids. Physics, controls, hitboxes (26×26), pushing,
HUD and everything else are untouched; only `Hero.draw` picks a different image.

**Switch** in `config.js`:

```js
characterSkin: { mode: 'custom', height: 48, p1: 'rae', p2: 'gina', flip: true },
// mode 'classic' = the default kids
```

or for a quick look without editing: `index.html?skin=classic`, `?skin=custom&skinHeight=40`.

**Files** (`assets/characters/custom/`)

| File | What |
|---|---|
| `source/gina-q-version.png`, `source/rae-q-version.png` | the supplied 1024×1536 RGBA portraits, kept unmodified. They were taken from the WebP copies attached in chat (the named PNG originals were not on disk); replace them with the true originals and re-run the build if those differ. |
| `gina-32/40/48.png`, `rae-32/40/48.png` | game-ready sprites |
| `skins.js` | sizes and foot anchors (generated) |

Rebuild with `python3 tools/build_custom_skins.py`: trims transparent padding, scales both
portraits by one common factor (relative size preserved), premultiplied area averaging (no dark or
white fringes), alpha snapped to on/off for crisp nearest-neighbour edges, and records each sprite's
foot anchor (centre of the shoes) so the figure, not the hair, is centred over the hitbox.

**Rendering**: the sprite's bottom row sits on the hitbox's feet line and its foot anchor on the
hitbox centre. It mirrors when the player last walked left (`flip`), bobs 1 px while walking on a
platform, and blinks by transparency during the usual 1 s after damage. No other animation.

**Size comparison** (`docs/reference/custom-skins/sizes-and-classic.png`, same scene):

| Height | Sprite (w×h) | Reads as |
|---|---|---|
| 32 px | 16×32 | silhouettes and hair colour only; faces are a few pixels |
| 40 px | 20×40 | hairstyles and outfits clear, faces suggested |
| **48 px (default, approved by Eventmatic 2026-11-12)** | 24×48 | eyes, blush and mouth visible; still narrower than the 26 px hitbox and 30 % of an 80 px platform; two players side by side do not overlap |

Known effect: a 48 px figure extends 22 px above the 26 px hitbox, so near the ceiling the head
disappears into the spike strip a moment before ceiling damage registers (damage still uses the
unchanged hitbox).

## Animated custom characters (prototype, 2026-11-12)

`tools/build_custom_anim.py` turns a 48 px custom sprite into a 12-frame animated sheet
(`assets/characters/custom/<name>-anim.png`, 40×52 frames, one row) plus `anims.js`.

| Frames | State | Used when |
|---|---|---|
| 0, 1 | idle (1 = blink + 1 px breath) | on a platform, no input; blink about every 2.6 s |
| 2–7 | walk (6 frames, 90 ms each) | on a platform with left/right input; mirrored for left |
| 8, 9 | fall (legs up and apart, arms spread) | not on a platform |
| 10 | land (crouch) | first 110 ms after touching down |
| 11 | hurt (squeezed eyes, open mouth, arms up) | first 350 ms after damage; the existing 1 s transparency blink still runs |

**How identity is kept**: head, face and hair pixels are copied unchanged from the 48 px sprite
(Rae's long hair also as a separate back layer that trails and lifts). The photo poses cannot walk,
so arms and legs are redrawn as simple outlined pixel limbs in colours sampled from the portrait
(jeans light/mid/dark, white sneakers, Gina's black jacket sleeves, Rae's pale tee). Gina's torso
(jacket, hoodie, belt bag) is kept from the portrait; Rae's tee and belt are redrawn because her
clasped arms cover them. Idle keeps each signature pose: Gina's hands on cheeks, Rae's clasped hands.

**Anchors**: every frame has the feet centre at x = 20 and the shoe soles on row 51, so the
renderer places all frames identically over the unchanged 26×26 hitbox (no float or sink between
frames). Frames are drawn 1:1 with nearest-neighbour sampling.

**Switches**: `characterSkin.animated` (default true); `?animated=0` shows the static portraits.

**Adding a character**: add an entry to `CHARACTERS` in `tools/build_custom_anim.py` (feet centre,
head/torso/hip/shoe rows, eye boxes, mouth point, read off a zoomed 48 px sprite), run
`tools/build_custom_skins.py` then `tools/build_custom_anim.py`, and set `characterSkin.p1/p2`.

**Known limits** (see `docs/reference/custom-skins/static-vs-animated.png`): the redrawn jeans are
slimmer and flatter than the painted originals; Rae's idle clasp reads as one diagonal forearm;
Gina's hands stay at her cheeks in the head pixels during every state (they read as cheeks at
48 px). Faces are unchanged from the approved static version, so readability is the same.

Previews: `anim-sheets.png` (all frames), `ingame-walk-cycle.png` (six walk frames captured from
the running game), `static-vs-animated.png` (same scene, plus a fall and a landing).

## Character library (2026-11-13)

Seven friends can be assigned to either player: **Gina, Rae, Ariel, Cindy, Ken, Linda, Sandy**. Player identity (1P / 2P, controls ← → / Z C, colours, HUD side, 26 px hitbox) never depends on the character.

**Registry:** `assets/characters/custom/characters.js` (`window.SHOT_CHARACTERS`). Each entry: `id`, `name` (display name), `source` (full-resolution portrait). Optional: `animated: false`, `flip: false`, and any custom fields (ignored by the game). Rendering metadata is generated: `skins.js` (32 / 40 / 48 px sprite size and foot anchor per id) and `anims.js` (animation sheets, Gina and Rae only). To add a friend: put `<id>-q-version.png` in `source/`, add an entry, run `python3 tools/build_custom_skins.py`.

**Pipeline:** unchanged from Gina / Rae (trim alpha > 16, premultiplied area average, alpha snapped at 50 %, foot anchor = centre of the shoes). The shared scale stays pinned to the approved Gina / Rae set, so their sprites are byte-identical; a newcomer taller than the target is capped. 48 px results: Ariel 27×47, Cindy 23×48, Ken 19×48, Linda 23×46, Sandy 24×47 (Gina 24×48, Rae 24×47).

**Sources:** the five portraits arrived as WebP chat attachments (1023–1024 × 1536–1537, with alpha). They were decoded once to PNG without editing (`source/<id>-q-version.png`); replace them with your original PNG files if you have them and rerun the build. Attachment order mapped to names as listed: hat + red scarf → Ariel, brown newsboy cap → Cindy, black cap + red tee → Ken, red hair → Linda, light-brown hair + blue dress → Sandy.

**Animation:** all seven use the same rig, frames and timing (`tools/build_custom_anim.py`): idle with blink, 6-frame walk, fall, land, hurt. Head, face, hair and hats are the portrait pixels; torso, arms and legs are redrawn in colours sampled from each portrait (Ariel: coat, red scarf, coat tails, hand at the hat when idle; Cindy: cardigan, skirt, bare legs, leg warmers, boots; Ken: red tee, crossed arms when idle; Linda: blue shirt, cream trousers; Sandy: sleeveless blue dress, bare legs). Gina's and Rae's sheets are byte-identical to before. As with Gina and Rae, the redrawn limbs are simpler than the painted portraits, and mirroring flips the lettering on Ariel's hat and Ken's cap.

**Selection:** optional, on the existing title screen (no extra step). 2P cycles with Z / C, 1P with ← / → (movement keys do nothing else before a round), or the small arrows by each name (semantic buttons). The other player's current character is skipped. Enter starts as before; Space still does not. The choice is kept across rematches and quits until changed; it is not stored across page reloads. API: `ShotStairs.characters()`, `ShotStairs.setCharacter('p1' | 'p2', id)`; event `characterChange`. `players.pN.name` still overrides the character's name.

**Verification:** `tests/character-tests.js` (11 checks): library and metadata, all 7 characters in both slots with identical walk / push traces to the default pair and a 26 px hitbox, five pairings with result names and rematch persistence, keyboard / pointer selection, name override, no errors. Full harness 135/135; deterministic trace identical to `8fc7181` (default pair). Captures in `docs/evidence/characters/`; gallery fixture `tests/characters-gallery.html`.
