# Character sprites and future skins

Character art is completely separate from gameplay. The engine moves a 26×26 collision box
(`HERO_WIDTH`) and only asks the renderer to draw "frame N of this player's sheet at the feet
position". Swapping the sheet never changes physics.

## Sheet layout (same as upstream `led.png`)

* PNG, 240×60, transparent background.
* Frames are 26×26 at x = 2, 32, 62, 92, 122, 152, 182, 212.
* Row y = 2: normal frames. Row y = 32: the same frames in the "hurt" flash colours.
* Frame use (facing right; the engine mirrors for left):

| x | frame |
|---|---|
| 2 | standing, idle |
| 32 / 62 / 92 | walk cycle (engine plays 62, 32, 62, 92) |
| 122 / 152 | falling, no steering |
| 182 / 212 | falling while steering |

Feet are at the bottom of the frame; keep the figure within the 26×26 cell.

## Defaults

`assets/kid-p1.png` (pink shirt, red cap) and `assets/kid-p2.png` (green shirt, blue cap) are
generated by `tools/build_sprites.py` from text bitmaps and palettes (`KID`, `KID_PALETTES`).
Edit the bitmap or palette and re-run the script to change the defaults.

## Using a custom sheet (e.g. a friend's pixel portrait)

```js
// config.js
players: {
  p1: { label: 'RAE',   keys: {...}, sheet: 'skins/rae.png' },
  p2: { label: 'LINDA', keys: {...}, sheet: 'skins/linda.png' }
}
```

or at runtime before the next round: `ShotStairs.configure({ players: { p1: { sheet: 'skins/rae.png' } } })`
(takes effect on the next page load because sheets are loaded once at start-up).
Any other sprite can be replaced the same way through `SHOT_CONFIG.sprites` using the keys in
`ShotSprites.MANIFEST` (e.g. `{ mug: 'skins/cocktail.png' }`).

No avatar editor or photo upload exists yet; this is only the file-level hook.
